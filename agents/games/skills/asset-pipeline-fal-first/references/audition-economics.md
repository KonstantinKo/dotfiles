# Early audition and total-cost decisions

Read this when choosing a construction/surface route or comparing pipeline efficiency. The aim is the least total effort to the requested achieved quality, not the smallest provider invoice. A static-prop result cannot establish superiority for organic forms, characters, articulated assets or architecture.

## Decide whether an audition can answer the real question

Search the existing library first, then make a bounded search of suitable free/license-clean sources when likely to help. Inspect actual candidates and their licenses; record why promising ones fail. Reuse a passing source without an audition. Use a sufficient supplied concept directly; a new concept is not an admission ticket to 3D generation.

For new construction, prefer one small specialized-3D audition before substantial bespoke geometry or surface engineering when an available fal.ai endpoint plausibly supplies the hardest visible form or finish. State what the output could replace and what would still need authoring. Choose the smallest call whose supported quality and output can answer that question; a cheap mode that destroys decisive detail is a false economy. Do not benchmark a roster of providers by default.

Skip or narrow the audition when evidence favors another route: exact interfaces dominate; required thin/hollow structures or deformation are unsupported; a useful source/method is already proven for this requirement; the requested task is material-only; tooling/input access is missing; or paid work is outside authorization. A mechanical or modular label alone does not forbid generation, nor does an organic label establish its suitability. An explicit user method takes precedence. If fal.ai is unavailable, use another authorized available method and record the reason; the skill must remain useful without fal tools.

Before any paid call, discover the exact endpoint's current supported inputs/outputs and price. Use its pricing tool when available; otherwise use authoritative current pricing. Record endpoint ID, pricing source/time, billable unit, planned options/quantity and estimate. Do not borrow a nearby endpoint's price or a historical unit rate. If a defensible estimate cannot be established, choose a nonpaid path while resolving it. Apply session/project authorization and shared ceilings; this skill supplies no dollar cap or spending permission.

Reserve estimated charges including outstanding and uncertain jobs. Persist input hashes, settings/seed, intent and returned job ID before waiting. Reconcile timeouts before any resubmission. An HTTP success or provider-complete status is not a usable artifact. Save the generated source and inspect its actual geometry and texture bindings under suitable views. Record estimated, confirmed and uncertain charges separately; never drop failed paid attempts.

## Compare, retain, then combine

Compare the original reference, incumbent if present, and imported candidate at comparable framing, target scale, lighting and exposure. Use actual artifact renders, not a provider thumbnail. Include the identity-carrying detail and a useful alternate view; investigate hidden geometry only to the degree required by visibility, fit or motion. If there is no incumbent, compare against the reference and explicit criteria; do not fabricate a completed authored alternative just for symmetry.

Record visual fidelity, construction/function and technical integrity separately. An audition may be useful despite failing an endpoint gate: for example it can supply a strong body and surface while joints need rebuilding. Make that repair estimate explicit before selection. Rank viable routes using the observed quality and remaining work, including topology, materials, articulation, export and runtime needs. Do not discard a stronger incumbent because the latest candidate is easier to describe or cheaper to generate. Preserve its source, evidence and revision so unsuccessful finishing can be rolled back without losing good work.

Use hybrid construction when it preserves the visual advantage: keep generated visual mass or surface character and author exact structural regions, interfaces, negative spaces or separately moving parts. Check the hybrid seam, contact and material continuity on real geometry before broad rebuilding. For characters, generated static shape does not satisfy topology, rig or deformation requirements; for modular architecture, attractive elevations do not prove thickness, connector fit or walkable openings. Material extraction or retexturing can be the useful audition when existing geometry already passes.

After initial review, assign at most one bounded targeted correction for the dominant diagnosed failure. If that defect persists, invoke the [method-review boundary](visual-quality.md): falsify the diagnosis and switch effective method, selectively replace the failing region, or escape to the stronger retained/source candidate. Do not reset this boundary by renaming the revision or replacing the worker. A chosen escape must address the observed failure; further work remains bounded by the actual task resources. Missing quality at a real boundary is an incomplete outcome, never a cheaper success.

## Account for the whole job

Keep one compact ledger, updated at handoffs rather than through excessive polling. Use native session/usage records when available, and preserve their scope and source. Record:

- Agent/session identifier, actual model and effort, role (maker, coordinator/parent, reviewer, replacement), work category and native input/output/cache token fields as exposed. Record unavailable fields as unknown. Replacement workers and failed attempts remain attributed to the same job.
- Native token totals with the source's semantics: do not add cached-input subsets to already inclusive input totals, or reasoning subsets twice. Separate cumulative snapshots from per-call usage so resumption does not double count. A turn count or visible transcript size is not measured token usage.
- Provider endpoint/job, generation type including concept/texture/3D, billable quantity, confirmed/estimated/uncertain cost and currency. Built-in generation with unknown USD stays unknown, not zero. Convert tokens to money only with a valid pricing basis; keep estimates distinguishable from bills.
- Parent orchestration, independent reviews, replacements, shared research/tooling and evaluation overhead. For comparisons, state how shared cost is allocated and retain unallocated totals; do not charge every arm the full shared expense or omit it. Separate reusable method development from asset fulfillment while reporting both.
- Wall-clock start/end and total elapsed, provider waiting, local render/build and active effort when measurable. Concurrent waits overlap; their sum is not elapsed time. Preserve unknown timing rather than inferring a precise measure from sparse events.
- Bytes retained and cleanup scope, unsuccessful auditions/corrections, final evidence and exact achieved endpoint. Report visual failures beside expenses.

Compare cost at equivalent achieved quality and delivery scope. If neither candidate passes, report the relative quality and spend of two incomplete results; do not calculate a successful-asset efficiency claim. Technical export success, source visual acceptance, runtime acceptance and user acceptance remain distinct gates. A source request requires no invented engine exercise; a runtime request cannot be finished by relabeling a source deliverable.
