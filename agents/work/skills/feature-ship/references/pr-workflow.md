# Verification and publication

Read the repository’s current instructions and required checks; they override these defaults. Platform requires full `bun run verify` and its architecture/decision gate on the latest head before readiness. Backend defaults to `npm run typecheck && npm run lint && npm run prettier && npm run test:unit`; integration needs `sst bind`/AWS and follows repository instructions.

Publication requires explicit authorization already in the session. Explicit invocation of this end-to-end skill authorizes its stated ticket/PR actions; carry that authorization forward. If absent, prepare the concrete draft and checks before requesting authorization. Add `(Written by {model name & version} for Konstantin)` to external posts, including ticket/PR bodies and any permitted replies. Use the repository PR template first, applying `pr` writing guidance within it; use its fallback template only when the repository has none.

Before pushing, run the available CodeRabbit CLI review/fix cycle unless its bot reviewed the current head; always read and address its findings. Include hook rewrites and complete affected review/checks after fixes. After every push and before completion, refresh the exact PR head, read all unresolved threads and review bodies, verify findings against current code, fix accepted findings silently, and resolve addressed bot threads. For skipped findings, reply briefly with reason and file:line evidence plus the required footer. Leave human threads for human resolution. Keep a PR draft while required gates are pending where supported; report ready only after the latest head satisfies repository checks, reviews, and decision gates.
