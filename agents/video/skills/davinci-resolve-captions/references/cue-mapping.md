# Map speech cues to the Resolve edit

Build a cue table in separate coordinate columns: spoken-audio source and time, source in point, timeline clip start and record time, cue text or word, Fusion-local frame if a title uses it, and the method used to confirm timing. A timeline item start is a record position; its source in point is a different coordinate. A Fusion comp's local frame zero may also differ from either. Do not infer these origins from the timecode display. Follow the shared [timeline frame conventions](../../davinci-resolve/references/timeline-media-render.md).

For a normal-speed 1x segment, `record time = timeline clip start + (source cue time - source in time)`. For example, a word at source time 2.5 s in media trimmed from 2.0 s begins 0.5 s after the clip's timeline start. Convert that elapsed offset using the timeline's actual frame rate, then snap once to the intended timeline frame. At fractional rates, use the confirmed timebase rather than treating a rounded label such as 23.976 or 29.97 as an integer rate. Keep drop-frame timecode notation separate from elapsed seconds: `01:00:00:00` is not a general instruction to add 3,600 × 29.97 frames, and it does not establish the source or Fusion-local origin.

Use piecewise source-to-record mapping wherever the audible source has speed changes, reverse playback, freezes, or edits. Do not carry a 1x offset through a retime. When picture cuts to B-roll while dialogue continues, captions remain tied to the audible timeline dialogue across that cut unless the edit intentionally changes the dialogue.

Treat SRT timestamps as cue ranges, usually phrase-level; they do not imply word-level timing. For word animation, start with supplied word timestamps or mark word boundaries by listening against the audio. Never divide a phrase evenly to manufacture sync. After import or placement, check cue starts and ends at the timeline frame rate, especially across trims, speed edits, nested timelines, and cutaways.
